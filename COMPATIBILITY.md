# Compatibility

Tools that read `.mbmap` files, and which parts of the format ([SPEC.md](SPEC.md)) each one supports.

## Tools

| Tool | What it is | What it does with a map |
|---|---|---|
| <img src="https://raw.githubusercontent.com/nobrega8/modbench/main/assets/icon.svg" width="20" height="20" alt="" align="top"> [Modbench](https://github.com/nobrega8/modbench) | Modbus TCP/UDP/RTU/ASCII client for Windows, Linux and macOS, with a command line (`modbench-cli`) and an MCP server | Opens a map and reads (and writes) the device by register name; browses and downloads this library; runs a simulated device shaped after a map. From the command line: `validate` and `convert` maps, and `map` reads every register of a map from a device; the MCP tools `read_map` and `validate_map` do the same for an AI assistant |
| <img src="assets/tools/scanbus-br.png" width="20" height="20" alt="" align="top"> [ScanBus-BR](https://github.com/ortegahernandes/ScanBus-BR-Simulator-Modbus) | Free Modbus RTU/TCP master, slave simulator and RTU sniffer for Windows and Linux (from version 5.2.0) | Searches this library and shows a device's registers (name, function, address); imports the register names as aliases and fills in the function, start address, type and byte order of the first register, plus the map's unit ID, baud rate, parity and stop bits. Its main table reads contiguous blocks (a start address and a count), not single registers by name; clicking a register opens that register in a separate window. From 5.3.0 a registers window lists all the registers of the selected device, with a filter, a function group selector and a firmware selector (5.3.1; alpha). Shows each map's status, and saves a map as CSV (the registers only), TXT or RTF (with descriptions and notes) |
| <img src="assets/tools/mtui.png" width="20" height="20" alt="" align="top"> [MTUI](https://github.com/inowattio/MTUI) | Keyboard-driven Modbus TCP/RTU client for the terminal, for Windows, Linux and macOS, with a web demo (from version 1.6.0) | Imports a pasted map: each register is pinned and labelled with its name and unit, and gets a rule that decodes its type, byte and word order, scale, offset and translation table. Registers it cannot decode (strings, multi-bit fields) keep only their label |
| <img src="assets/tools/modbus-tools.png" width="20" height="20" alt="" align="top"> [Modbus Tools](https://github.com/serhmarch/ModbusTools) | Modbus client (ModbusClient) and server simulator (ModbusServer) for Windows and Linux, with TCP, UDP, RTU and ASCII (not yet in a release: the support is merged on the `v0.5dev` branch) | **Data › Import Data View…** and **Import Items…** accept a `.mbmap.json` file: each register becomes a data view item (address, format, byte and word order, and a comment with the name, unit, scale and offset), and the view is named after the map. Bit fields and `bool` bits in a register become one `Bin16` item per register, its comment naming each bit. Export is unchanged |
| <img src="assets/tools/open-modscan.png" width="20" height="20" alt="" align="top"> [Open ModScan](https://github.com/sanny32/OpenModScan) | Free Modbus master (client) for Windows and Linux (merged on the `dev` branch, not in a release yet: 1.16.2 does not have it) | File › Open accepts a `.mbmap.json` file: the registers are grouped into windows by area, display mode and byte order (gaps of up to 10 addresses, within the read limits), each set up with the point type, start address, length, device ID, address base and display mode, and the register names (with unit and scale) as address descriptions. A map with more than 8 windows opens a list to choose from. File › Device Map Library downloads this library's index, lists the maps with a filter, and opens the one picked |

## Adding a tool

Building a tool that reads `.mbmap`? Follow [SPEC.md](SPEC.md) and check it against the sample files in [`tests/`](tests/): each one lists the diagnostics a reader must report. Then open a pull request that adds your tool to this page, with what it supports. Partial support is fine: say which parts it reads and which it ignores.
