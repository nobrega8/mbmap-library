# Modbus RTU, Modbus TCP ও RS-485

তিনটি নাম যা প্রায়ই গুলিয়ে যায়।

| | Modbus RTU | Modbus TCP |
|---|---|---|
| মাধ্যম | সিরিয়াল লাইন, প্রায় সবসময় RS-485 (কখনও RS-232) | Ethernet বা Wi-Fi |
| ঠিকানা | বাসে unit ID 1–247 | IP ঠিকানা ও পোর্ট (502), সঙ্গে একটি unit ID |
| ত্রুটি যাচাই | প্রতিটি ফ্রেমে CRC-16 | TCP-র নিজস্ব যাচাই; CRC নেই |
| ফ্রেমিং | ফ্রেমের মাঝে 3.5 অক্ষরের নীরবতা | দৈর্ঘ্যসহ 7-বাইট হেডার (MBAP) |
| প্রতি লিঙ্কে ডিভাইস | প্রতি সেগমেন্টে 32 ইউনিট লোড পর্যন্ত (কম-লোড ট্রান্সসিভারে আরও), একটি মাস্টার | প্রতি ডিভাইসে একাধিক ক্লায়েন্ট, ডিভাইসের সীমা পর্যন্ত |
| সাধারণ গতি | 9600–115200 baud | 10/100 Mbit/s, ডিভাইসের সীমা পর্যন্ত |

**RS-485** শুধু বৈদ্যুতিক স্তর: দুটি তার, একটি ডিফারেনশিয়াল সিগন্যাল, একটি বাস। Modbus RTU এর ওপর চলে, অন্য প্রোটোকলও চলে (BACnet MS/TP, DMX, RS-485 অ্যাডাপ্টারে M-Bus)।

**Modbus ASCII** একই অনুরোধ পড়ার যোগ্য হেক্স টেক্সট হিসেবে পাঠায়; আজ এটি বিরল।

## একই রেজিস্টার

পরিবহন যা-ই হোক, রেজিস্টার ম্যাপ একই: যে ডিভাইস দুটিই দেয়, সে একই ঠিকানা, ধরন ও স্কেলে উত্তর দেয়। বদলায় শুধু তার কাছে পৌঁছানোর উপায়: RTU-তে সিরিয়াল সেটিং ও unit ID, TCP-তে IP ঠিকানা ও পোর্ট।

## গেটওয়ে

একটি Modbus TCP-থেকে-RTU গেটওয়ে Ethernet টুলকে সিরিয়াল ডিভাইসে পৌঁছাতে দেয়। TCP অনুরোধের unit ID সিরিয়াল দিকের ডিভাইস বাছাই করে। গেটওয়ে নিজস্ব টাইমআউট যোগ করে; এর পেছনের কোনো ডিভাইস উত্তর না দিলে আগে গেটওয়ের সিরিয়াল সেটিং যাচাই করুন।

## MBMap ম্যাপ এটি কীভাবে নথিভুক্ত করে

একটি ম্যাপ বলে ডিভাইস কোন পরিবহন দেয় (`protocol`: `rtu`, `tcp` বা দুটিই) এবং সেগুলোর ডিফল্ট (`baudrate`, `parity`, `databits`, `stopbits`, `port`, `unit_id`)।
