# Modbus unit ID (স্লেভ ID): কোন ডিভাইস উত্তর দেয়

প্রতিটি Modbus অনুরোধে এক বাইটের একটি unit ID থাকে, যাকে স্লেভ ID, স্লেভ ঠিকানা বা ডিভাইস ঠিকানাও বলা হয়।

## RS-485 (Modbus RTU) তে

- বাসের প্রতিটি ডিভাইসের নিজস্ব ঠিকানা 1 থেকে 247, যা তার ডিসপ্লে, DIP সুইচ বা কনফিগারেশন সফটওয়্যার দিয়ে ঠিক করা হয়।
- ঠিকানা 0 হলো ব্রডকাস্ট: প্রতিটি ডিভাইস লেখাটি কার্যকর করে এবং কেউ উত্তর দেয় না। 0-তে পাঠানো পড়ার কোনো জবাব আসে না।
- অন্য ঠিকানায় সেট করা ডিভাইস আপনার অনুরোধ পুরোপুরি উপেক্ষা করে, তাই ভুল unit ID মৃত ডিভাইসের মতো দেখায়: আপনি ত্রুটি নয়, [টাইমআউট](modbus-timeout-no-response) পান।

## Modbus TCP তে

- সরাসরি IP দিয়ে পৌঁছানো ডিভাইস সাধারণত unit ID উপেক্ষা করে বা 1 আশা করে। কেউ 0 বা 255 আশা করে, আর কয়েকটি নিজেদের কনফিগার করা মান ছাড়া কিছুই নেয় না।
- TCP-থেকে-RTU গেটওয়ের পেছনে unit ID সিরিয়াল ডিভাইস বাছাই করে: সেটি ওই ডিভাইসের RS-485 ঠিকানার সঙ্গে মিলতে হবে। গেটওয়ে নিজে প্রায়ই 0, 255 বা কনফিগার করা ID-তে উত্তর দেয়।
- একাধিক অভ্যন্তরীণ অংশসহ কিছু ডিভাইস (মিটার ও ব্যাটারিসহ ইনভার্টার) প্রতিটি অংশের জন্য আলাদা unit ID-তে উত্তর দেয়।

## অজানা ঠিকানা খোঁজা

- ডিভাইসের ডিসপ্লে বা লেবেল থেকে পড়ুন।
- স্ক্যান করুন: ডিভাইসের baud রেটে 1 থেকে 247 পর্যন্ত প্রতিটি ঠিকানায় একটি সাধারণ রেজিস্টারের পড়া পাঠান এবং দেখুন কে উত্তর দেয়। শুধু সেই ডিভাইসটি জুড়ে করুন।
- ফ্যাক্টরি সেটিংয়ে রিসেট করুন; ম্যানুয়াল ডিফল্ট বলে দেয় (প্রায়ই 1)।

## MBMap ম্যাপ এটি কীভাবে নথিভুক্ত করে

একটি ম্যাপ ডিভাইসের ডিফল্ট `unit_id` দেয় (এবং সিরিয়াল সেটিং ও TCP পোর্টও)। ডিফল্ট কেবল একটি শুরুর বিন্দু: ইনস্টলের সময় ডিভাইস সাধারণত নতুন করে কনফিগার করা হয়।
