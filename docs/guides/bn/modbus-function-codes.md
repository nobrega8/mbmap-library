# Modbus ফাংশন কোড ও রেজিস্টার ক্ষেত্র

প্রতিটি Modbus অনুরোধ একটি ফাংশন কোডের নাম বলে। সেটিই ঠিক করে কাজ কী হবে এবং ডিভাইসের কোন ক্ষেত্রের ওপর হবে।

| কোড | নাম | ক্ষেত্র | আকার |
|---|---|---|---|
| 01 | Read Coils | কয়েল (0x) | বিট, পড়া/লেখা |
| 02 | Read Discrete Inputs | ডিসক্রিট ইনপুট (1x) | বিট, শুধু পড়া |
| 03 | Read Holding Registers | হোল্ডিং রেজিস্টার (4x) | 16-বিট, পড়া/লেখা |
| 04 | Read Input Registers | ইনপুট রেজিস্টার (3x) | 16-বিট, শুধু পড়া |
| 05 | Write Single Coil | কয়েল | চালু করতে `0xFF00`, বন্ধ করতে `0x0000` লিখুন |
| 06 | Write Single Register | হোল্ডিং রেজিস্টার | একটি রেজিস্টার |
| 15 (0x0F) | Write Multiple Coils | কয়েল | একাধিক বিট |
| 16 (0x10) | Write Multiple Registers | হোল্ডিং রেজিস্টার | একাধিক রেজিস্টার |
| 17 (0x11) | Report Server ID | — | ডিভাইসের পরিচয়, ফরম্যাট ডিভাইস ঠিক করে |
| 43 / 14 (0x2B/0x0E) | Read Device Identification | — | বিক্রেতা, পণ্য কোড, সংস্করণ টেক্সট হিসেবে |

## হোল্ডিং না ইনপুট?

ম্যানুয়ালের সারণি বা তার ঠিকানার উপসর্গ আপনাকে বলে দেয়: `3xxxx` পড়া হয় 04 দিয়ে, `4xxxx` 03 দিয়ে। কিছু ডিভাইস দুটি ফাংশনেরই একই ডেটা দিয়ে উত্তর দেয়; অন্যরা ভুলটিকে এক্সসেপশন 01 (illegal function) দিয়ে প্রত্যাখ্যান করে। ম্যানুয়াল কোনো উপসর্গ বা ফাংশন না দিলে আগে 03 চেষ্টা করুন।

## লেখা

- একটি 32-বিট মানের দুটি রেজিস্টার 16 দিয়ে একসঙ্গে লিখতে হয়; 06 দিয়ে এক এক করে অর্ধেকগুলো লিখলে ডিভাইসে মিশ্র মান থেকে যেতে পারে, বা তা প্রত্যাখ্যাত হতে পারে।
- কিছু ডিভাইস শুধু 06 নেয়, কেউ শুধু 16। ম্যানুয়ালের সমর্থিত ফাংশনের তালিকা তা ঠিক করে দেয়।
- 05 দিয়ে লেখা কয়েলে ঠিক `0xFF00` বা `0x0000` থাকতে হবে।

## MBMap ম্যাপ এটি কীভাবে নথিভুক্ত করে

প্রতিটি রেজিস্টারে একটি `area` (`coil`, `discrete`, `input`, `holding`) ও একটি `access` (`R`, `W`, `RW`) থাকে; টুল সেগুলো থেকেই ফাংশন বেছে নেয়। ম্যাপ পরিচয়ের ফাংশন 17 ও 43-ও বর্ণনা করতে পারে, যাতে টুল যাচাই করতে পারে সে কোন ডিভাইসের সঙ্গে কথা বলছে।
