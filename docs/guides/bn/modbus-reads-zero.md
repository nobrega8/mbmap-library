# একটি Modbus রেজিস্টার 0, 0xFFFF বা 0x8000 পড়ছে

অনুরোধ সফল হয়, কিন্তু মানটির কোনো অর্থ নেই। ডিভাইসকে সন্দেহ করার আগে দেখুন সে আপনাকে কী বলার চেষ্টা করছে।

## সাধারণ কারণ

- **ভুল ক্ষেত্র।** একই ঠিকানা ইনপুট ও হোল্ডিং রেজিস্টার, দুই রূপেই ভিন্ন বিষয়বস্তুসহ থাকতে পারে। মান ইনপুট রেজিস্টারে থাকলে হোল্ডিং রেজিস্টার পড়লে শূন্য ফিরতে পারে। [ফাংশন কোড](modbus-function-codes) দেখুন।
- **এক ঘরের সরে যাওয়া।** 32-বিট মানের প্রথম অর্ধেকের বদলে দ্বিতীয় অর্ধেক পড়লে ছোট মানের জন্য প্রায়ই 0 আসে। [ঠিকানা](modbus-address-off-by-one) দেখুন।
- **বাস্তবায়িত নয়।** অনেক ডিভাইস অব্যবহৃত রেজিস্টার পড়ার জবাবে এক্সসেপশনের বদলে 0, 0xFFFF, 0x7FFF বা 0x8000 দেয়। SunSpec ডিভাইস চিহ্নযুক্ত ফিল্ডে «বাস্তবায়িত নয়» বোঝাতে 0x8000 (−32768) এবং চিহ্নহীন ফিল্ডে 0xFFFF ব্যবহার করে।
- **মাপা হয়নি।** তিন-তার সংযোগে নিউট্রাল কারেন্ট, তার না লাগানো ফেজ, বা কিছু না জোড়া সেন্সর ইনপুট 0 বা একটি নির্দিষ্ট চিহ্ন পড়ে।
- **প্রস্তুত নয়।** কিছু ডিভাইস পাওয়ার-আপের পর কয়েক সেকেন্ড, বা প্রথম মাপার চক্র শেষ না হওয়া পর্যন্ত, শূন্য ফেরত দেয়।
- **মডেলের পার্থক্য।** পরিবারের ম্যানুয়ালে তালিকাভুক্ত রেজিস্টার শুধু কিছু মডেলে থাকতে পারে: বাকিগুলো 0 ফেরত দেয়।
- **স্কেল খুব মোটা।** 1 A স্কেলে ছোট কারেন্ট 0 পড়া হয়।

## MBMap ম্যাপ এটি কীভাবে নথিভুক্ত করে

একটি ম্যাপ `sentinels` তালিকাভুক্ত করতে পারে, অর্থাৎ প্রতিটি ধরনের সেই মান যার অর্থ «পাওয়া যায় না», যাতে টুল সেগুলোকে রিডিংয়ের বদলে অনুপস্থিত হিসেবে দেখায়। রেজিস্টারের বিবরণ জানায় কোনো মানের জন্য কোন মডেল বা ওয়্যারিং দরকার।
