# Modbus หมดเวลา: อุปกรณ์ไม่ตอบกลับ

การหมดเวลาหมายความว่าไม่มีสิ่งใดกลับมาที่เครื่องมือของคุณรับได้ ให้ไล่ตรวจรายการจากชั้นล่างสุดขึ้นไป

## Modbus RTU (RS-485)

1. **การเดินสาย** ผู้ผลิตแต่ละรายตั้งชื่อ A กับ B (หรือ D+ กับ D− หรือ + กับ −) ไม่เหมือนกัน หากไม่มีอะไรตอบ ให้สลับสายสองเส้น ไม่มีอันตราย
2. **กราวด์ร่วม** ต่อกราวด์สัญญาณ (GND, C, 0 V) หากอุปกรณ์มี สายยาวที่ไม่มีกราวด์ร่วมจะเกิดข้อผิดพลาดที่มาแล้วไป
3. **เทอร์มิเนชัน** ใส่ตัวต้านทาน 120 Ω ที่ปลายทั้งสองของบัส ไม่ใช่ที่อุปกรณ์ทุกตัว สายสั้นบนโต๊ะมักใช้งานได้โดยไม่ต้องมี
4. **การตั้งค่าซีเรียล** อัตราบอด บิตข้อมูล พาริตี และสต็อปบิตต้องตรงกันทุกประการ ค่าจากโรงงานที่พบบ่อยคือ 9600 หรือ 19200 บอด ข้อมูล 8 บิต พาริตีคู่หรือไม่มี พาริตีที่ไม่ตรงกันจะไม่มีเสียงเตือนใด ๆ
5. **Unit ID** อุปกรณ์ทุกตัวบนบัสต้องมีที่อยู่ของตัวเอง 1 ถึง 247 อุปกรณ์ที่ตั้งเป็น 1 จะไม่ตอบคำขอสำหรับ 2 ดู [unit ID](modbus-unit-id-slave-id)
6. **มาสเตอร์เดียว** มาสเตอร์สองตัวบนบัสเดียวกัน (PLC กับแล็ปท็อป) จะชนกัน
7. **ทิศทางของตัวแปลง** ตัวแปลง USB–RS-485 ราคาถูกบางครั้งสลับทิศทางช้าเกินไปที่อัตราบอดสูง ลองใช้อัตราที่ต่ำลง

## Modbus TCP

1. **เข้าถึงอุปกรณ์ให้ได้ก่อน** ลอง `ping` และตรวจสอบว่าพอร์ต 502 เปิดอยู่
2. **ขีดจำกัดการเชื่อมต่อ** อุปกรณ์หลายรุ่นรับการเชื่อมต่อ TCP ได้ไม่กี่การเชื่อมต่อ เครื่องมือที่ปล่อยการเชื่อมต่อค้างไว้อาจกันตัวอื่นไม่ให้เข้าได้จนกว่าอุปกรณ์จะตัดทิ้งเพราะหมดเวลา
3. **Unit ID ผ่านเกตเวย์** หลังเกตเวย์ TCP-เป็น-RTU unit ID เลือกอุปกรณ์ซีเรียลและต้องตรงกับที่อยู่ของอุปกรณ์นั้น เกตเวย์บางตัวต้องการ 0 หรือ 255 สำหรับตัวมันเอง
4. **เปิด Modbus TCP แล้วหรือยัง** อุปกรณ์บางรุ่นส่งมาโดยปิดไว้ หรือตอบเฉพาะที่พอร์ตอื่น

## อุปกรณ์ตอบบางคำขอแต่ไม่ตอบบางคำขอ

- คำขอที่ใหญ่เกินไป หรือที่ครอบคลุมช่องว่างในตารางรีจิสเตอร์ อาจได้รับข้อยกเว้นหรือถูกเมิน ให้อ่านบล็อกที่เล็กลง
- อุปกรณ์บางรุ่นต้องการช่วงพักระหว่างคำขอ (3.5 ช่วงตัวอักษรบน RTU และมากกว่านั้นสำหรับอุปกรณ์ช้า) เพิ่มช่วงเวลาการสอบถาม
- บางรุ่นตอบหลังหน่วงเวลาหลายสิบหรือหลายร้อยมิลลิวินาที ให้เพิ่มเวลารอคำตอบก่อนอย่างอื่น
