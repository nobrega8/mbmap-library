# รหัสข้อยกเว้นของ Modbus: อุปกรณ์กำลังบอกอะไรคุณ

เมื่ออุปกรณ์ Modbus เข้าใจคำขอแต่ทำตามไม่ได้ มันจะตอบด้วยข้อยกเว้น คือรหัสฟังก์ชันที่ตั้งบิตบนสุด (`0x83` สำหรับการอ่านโฮลดิงรีจิสเตอร์ที่ล้มเหลว) และรหัสหนึ่งไบต์

| รหัส | ชื่อ | สาเหตุที่พบบ่อย | สิ่งที่ควรลอง |
|---|---|---|---|
| 01 | Illegal function | อุปกรณ์ไม่รองรับรหัสฟังก์ชันนี้ เช่น อ่านอินพุตรีจิสเตอร์ (04) จากอุปกรณ์ที่มีแต่โฮลดิงรีจิสเตอร์ หรือเขียนด้วย 16 กับอุปกรณ์ที่รับแต่ 06 | ใช้รหัสฟังก์ชันที่คู่มือระบุสำหรับตารางนั้น |
| 02 | Illegal data address | ไม่มีที่อยู่นั้น หรือบล็อกที่ขอไปตกช่องว่าง | ตรวจ[การเยื้องที่อยู่](modbus-address-off-by-one) อ่านทีละน้อยรีจิสเตอร์ |
| 03 | Illegal data value | จำนวนมากเกินไป (เกิน 125 รีจิสเตอร์) หรือค่าที่เขียนอยู่นอกช่วง | อ่านบล็อกที่เล็กลง ตรวจช่วงที่อนุญาตก่อนเขียน |
| 04 | Server device failure | อุปกรณ์ขัดข้องขณะทำงานนั้น อุปกรณ์บางรุ่นใช้กับการเขียนที่ถูกปฏิเสธทุกกรณี หรือการอ่านบล็อกที่ไม่อนุญาต | อ่านทีละรีจิสเตอร์ ตรวจสถานะของอุปกรณ์ |
| 05 | Acknowledge | รับแล้ว แต่ต้องใช้เวลา (การโปรแกรม การบันทึก) | รอ แล้วสอบถามซ้ำ |
| 06 | Server device busy | อุปกรณ์ไม่ว่าง | ลองใหม่ภายหลัง |
| 0A | Gateway path unavailable | เกตเวย์เข้าถึงอุปกรณ์หลังมันไม่ได้ | ตรวจฝั่งซีเรียลของเกตเวย์และการกำหนดเส้นทาง |
| 0B | Gateway target failed to respond | เกตเวย์ส่งต่อคำขอแล้วแต่อุปกรณ์ไม่ตอบ | ตรวจ unit ID อัตราบอด และการเดินสายหลังเกตเวย์ |

## ไม่มีคำตอบเลยไม่ใช่ข้อยกเว้น

อุปกรณ์ที่ได้รับเฟรมที่ CRC ผิด unit ID ผิด หรือพาริตีผิดจะเงียบ คุณจะได้การหมดเวลา ไม่ใช่ข้อยกเว้น ดู[การหมดเวลา](modbus-timeout-no-response)

## บล็อกที่คร่อมช่องว่าง

อุปกรณ์หลายรุ่นปฏิเสธการอ่านที่ครอบคลุมที่อยู่ที่ไม่ได้ใช้ แม้ทุกรีจิสเตอร์ที่คุณต้องการจะมีอยู่ก็ตาม หากการอ่าน 20 รีจิสเตอร์ล้มเหลวด้วย 02 แต่อ่านทีละตัวได้ ให้แบ่งคำขอตามช่องว่าง แมปสามารถระบุได้ว่าอุปกรณ์รับกี่รีจิสเตอร์ต่อคำขอ (`max_read_registers`)
