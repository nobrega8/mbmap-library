# Modbus RTU, Modbus TCP และ RS-485

สามชื่อที่มักถูกสับสน

| | Modbus RTU | Modbus TCP |
|---|---|---|
| สื่อ | สายซีเรียล เกือบทุกครั้งเป็น RS-485 (บางครั้งเป็น RS-232) | Ethernet หรือ Wi-Fi |
| การกำหนดที่อยู่ | unit ID 1–247 บนบัส | ที่อยู่ IP และพอร์ต (502) พร้อม unit ID |
| การตรวจข้อผิดพลาด | CRC-16 ในทุกเฟรม | การตรวจสอบของ TCP เอง ไม่มี CRC |
| การจัดเฟรม | ความเงียบ 3.5 ช่วงตัวอักษรระหว่างเฟรม | เฮดเดอร์ 7 ไบต์ (MBAP) ที่มีความยาว |
| จำนวนอุปกรณ์ต่อลิงก์ | สูงสุด 32 หน่วยโหลดต่อเซกเมนต์ (มากกว่านั้นด้วยทรานซีฟเวอร์โหลดต่ำ) มาสเตอร์หนึ่งตัว | ไคลเอนต์จำนวนมากต่ออุปกรณ์ ขึ้นกับขีดจำกัดของอุปกรณ์ |
| ความเร็วทั่วไป | 9600–115200 บอด | 10/100 Mbit/s ขึ้นกับอุปกรณ์ |

**RS-485** เป็นเพียงชั้นไฟฟ้า สายสองเส้น สัญญาณดิฟเฟอเรนเชียล และบัส Modbus RTU ทำงานบนนั้น เช่นเดียวกับโปรโตคอลอื่น (BACnet MS/TP, DMX, M-Bus ผ่านอะแดปเตอร์ RS-485)

**Modbus ASCII** ส่งคำขอเดียวกันเป็นข้อความเลขฐานสิบหกที่อ่านได้ ปัจจุบันพบน้อย

## รีจิสเตอร์ชุดเดียวกัน

แมปรีจิสเตอร์เหมือนกันไม่ว่าจะส่งแบบใด อุปกรณ์ที่มีทั้งสองแบบตอบด้วยที่อยู่ ชนิด และสเกลเดียวกัน สิ่งที่ต่างคือวิธีเข้าถึง การตั้งค่าซีเรียลและ unit ID สำหรับ RTU ที่อยู่ IP และพอร์ตสำหรับ TCP

## เกตเวย์

เกตเวย์ Modbus TCP-เป็น-RTU ทำให้เครื่องมือ Ethernet เข้าถึงอุปกรณ์ซีเรียลได้ unit ID ของคำขอ TCP เลือกอุปกรณ์ฝั่งซีเรียล เกตเวย์มีเวลาหมดของตัวเองเพิ่มเข้ามา หากอุปกรณ์หลังเกตเวย์ไม่ตอบ ให้ตรวจการตั้งค่าซีเรียลบนเกตเวย์ก่อน

## แมป MBMap บันทึกเรื่องนี้อย่างไร

แมประบุว่าอุปกรณ์มีการส่งแบบใด (`protocol`: `rtu`, `tcp` หรือทั้งสอง) และค่าเริ่มต้นของมัน (`baudrate`, `parity`, `databits`, `stopbits`, `port`, `unit_id`)
