# รีจิสเตอร์ Modbus อ่านได้ 0, 0xFFFF หรือ 0x8000

คำขอสำเร็จ แต่ค่าที่ได้ไม่มีความหมาย ก่อนสงสัยอุปกรณ์ ให้ดูว่ามันพยายามบอกอะไรคุณ

## สาเหตุที่พบบ่อย

- **พื้นที่ผิด** ที่อยู่เดียวกันอาจมีทั้งเป็นอินพุตรีจิสเตอร์และโฮลดิงรีจิสเตอร์ที่มีเนื้อหาต่างกัน การอ่านโฮลดิงรีจิสเตอร์ทั้งที่ค่าอยู่ในอินพุตรีจิสเตอร์อาจได้ศูนย์ ดู[รหัสฟังก์ชัน](modbus-function-codes)
- **คลาดไปหนึ่ง** การอ่านครึ่งหลังของค่า 32 บิตแทนครึ่งแรกมักได้ 0 สำหรับค่าเล็ก ๆ ดู[ที่อยู่](modbus-address-off-by-one)
- **ไม่ได้ใช้งาน** อุปกรณ์หลายรุ่นตอบการอ่านรีจิสเตอร์ที่ไม่ได้ใช้ด้วย 0, 0xFFFF, 0x7FFF หรือ 0x8000 แทนที่จะเป็นข้อยกเว้น อุปกรณ์ SunSpec ใช้ 0x8000 (−32768) สำหรับ “ไม่ได้ใช้งาน” ในฟิลด์ที่มีเครื่องหมาย และ 0xFFFF ในฟิลด์ที่ไม่มี
- **ไม่ได้วัด** กระแสนิวทรัลของการต่อสามสาย เฟสที่ไม่ได้ต่อ หรืออินพุตเซนเซอร์ที่ไม่ได้ต่ออะไร จะอ่านได้ 0 หรือค่าเครื่องหมายคงที่
- **ยังไม่พร้อม** อุปกรณ์บางรุ่นคืนค่าศูนย์ในไม่กี่วินาทีหลังเปิดเครื่อง หรือจนกว่ารอบการวัดครั้งแรกจะเสร็จ
- **ความต่างระหว่างรุ่น** รีจิสเตอร์ที่ระบุในคู่มือของตระกูลอาจมีเฉพาะบางรุ่น รุ่นอื่นคืนค่า 0
- **สเกลหยาบเกินไป** กระแสเล็กที่สเกล 1 A จะอ่านได้ 0

## แมป MBMap บันทึกเรื่องนี้อย่างไร

แมปสามารถระบุ `sentinels` คือค่าที่หมายถึง “ไม่มีข้อมูล” ของแต่ละชนิด เครื่องมือจึงแสดงเป็นค่าที่หายไป ไม่ใช่ค่าที่วัดได้ คำอธิบายของรีจิสเตอร์ระบุว่าค่าต้องใช้รุ่นหรือการต่อสายแบบใด
