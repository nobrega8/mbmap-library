# Modbus 异常码：设备在告诉你什么

当 Modbus 设备理解了请求却无法执行时，它会用异常来应答：功能码的最高位置 1（读保持寄存器失败时为 `0x83`），再加一个字节的异常码。

| 代码 | 名称 | 常见原因 | 可以尝试 |
|---|---|---|---|
| 01 | 非法功能 | 设备不支持此功能码：对只有保持寄存器的设备用 04 读输入寄存器，或者对只接受 06 的设备用 16 写入 | 使用手册中该表所列的功能码 |
| 02 | 非法数据地址 | 地址不存在，或者请求的块跨入了空隙 | 检查[地址偏移](modbus-address-off-by-one)；一次少读几个寄存器 |
| 03 | 非法数据值 | 数量过大（超过 125 个寄存器），或写入的值超出范围 | 读取较小的块；写入前检查允许的范围 |
| 04 | 服务器设备故障 | 设备在执行时出错；有些设备对任何被拒绝的写入，或读取不允许的块，都用它 | 一次读一个寄存器；检查设备状态 |
| 05 | 确认 | 已接受，但需要一段时间（编程、保存） | 等待，然后轮询 |
| 06 | 服务器设备忙 | 设备正忙 | 稍后重试 |
| 0A | 网关路径不可用 | 网关无法连到其后面的设备 | 检查网关的串口侧及其路由 |
| 0B | 网关目标设备无响应 | 网关转发了请求，但设备没有应答 | 检查网关后面的单元 ID、波特率和接线 |

## 完全没有应答不是异常

设备收到 CRC 错误、单元 ID 错误或校验错误的帧时会保持沉默：你得到的是超时，而不是异常。参见[超时](modbus-timeout-no-response)。

## 跨越空隙的块

许多设备会拒绝任何覆盖未使用地址的读取，即使你需要的每个寄存器都存在。如果一次读 20 个寄存器以 02 失败，而逐个读取却成功，请在空隙处拆分请求。映射表可以说明设备每次请求接受多少个寄存器（`max_read_registers`）。
