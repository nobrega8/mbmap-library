# Modbus 地址：为什么读到的寄存器差了一位

你读取寄存器 40001，得到的却是手册中 40002 的值；或者设备对表里明明存在的寄存器返回了*非法数据地址*。几乎总是同一个原因：手册和你的工具对寄存器的计数方式不同。

## 同一个寄存器的三种写法

| 手册上印的内容 | 含义 | 线路上发送的内容 |
|---|---|---|
| `40001`（Modicon 引用） | 保持寄存器编号 1，从 1 开始计数，`4` 是区域前缀 | 地址 `0` |
| `1`（寄存器编号） | 保持寄存器 1，从 1 开始计数 | 地址 `0` |
| `0` 或 `0x0000`（偏移量） | 地址本身 | 地址 `0` |

Modbus 帧中携带的地址始终是 0 到 65535。前缀 `4`（保持）、`3`（输入）、`1`（离散输入）和 `0`（线圈）并不会发送：区域由功能码决定（03 为保持寄存器，04 为输入寄存器，02 为离散输入，01 为线圈）。剩下的数字常常从 1 开始计数，所以线路地址是该数字**减一**。

`400001` 或 `300013` 这类六位引用的处理方式相同：去掉第一位数字再减一（`300013` → 输入寄存器 `12`）。

## 如何判断手册用的是哪一种

- **十六进制地址**（`0x0BB7`、`1004h`）几乎总是线路地址。
- **首个寄存器为 40001 或 30001** 表示 Modicon 引用：减去 40001 或 30001。
- **首个寄存器为 1** 通常表示从 1 开始计数；首个寄存器为 0 表示线路地址。
- **找一个完整的示例。** 许多手册给出了请求帧（“读取寄存器 40011：01 03 00 0A 00 01 …”）。功能码后面的两个字节就是线路地址，一看便知。
- **有些手册混用几种写法**，例如十进制的“寄存器”列比旁边十六进制的“地址”列大 1。以十六进制列和示例帧为准。

## 你的工具期望什么

工具之间也有差别。有的要求线路地址，有的要求从 1 开始的寄存器编号，有的接受 Modicon 引用并自动去掉前缀。如果某个值恰好偏移了一个寄存器（32 位值看起来像乱码，或者每个值都像是相邻寄存器的内容），请试试把地址减一或加一。

## MBMap 映射表如何记录

每个 `.mbmap.json` 文件都用 `address_base` 说明其地址采用哪种约定：`0` 表示地址就是线路地址，`1` 表示地址从 1 开始计数，线路地址要减一。本站的设备页面、CSV 导出和 Home Assistant 导出会在映射表中原样写出的地址旁边显示线路地址，因此你无需猜测。
