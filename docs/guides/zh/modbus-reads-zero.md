# Modbus 寄存器读到 0、0xFFFF 或 0x8000

请求成功了，但数值毫无意义。在怀疑设备之前，先看看它想告诉你什么。

## 常见原因

- **区域错误。** 同一个地址可能同时存在输入寄存器和保持寄存器，内容各不相同。数值在输入寄存器里，却去读保持寄存器，可能返回零。参见[功能码](modbus-function-codes)。
- **差了一位。** 读到 32 位数值的后半部分而不是前半部分，对较小的值常常得到 0。参见[地址](modbus-address-off-by-one)。
- **未实现。** 许多设备对未使用寄存器的读取返回 0、0xFFFF、0x7FFF 或 0x8000，而不是异常。SunSpec 设备在有符号字段中用 0x8000（−32768）表示“未实现”，在无符号字段中用 0xFFFF。
- **未测量。** 三线连接的中性线电流、没有接线的相，或者没有接任何东西的传感器输入，读到 0 或一个固定标记。
- **尚未就绪。** 有些设备上电后的几秒内，或者在完成第一个测量周期之前，会返回零。
- **型号差异。** 系列手册中列出的寄存器可能只在部分型号上存在：其他型号返回 0。
- **比例太粗。** 比例为 1 A 时，很小的电流读作 0。

## MBMap 映射表如何记录

映射表可以列出 `sentinels`，即每种类型中表示“不可用”的值，这样工具会把它们显示为缺失，而不是读数。寄存器的说明会注明某个值需要哪些型号或接线方式。
