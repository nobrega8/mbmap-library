# Modbus 超时：设备没有应答

超时表示没有收到你的工具能够接受的任何应答。请从协议栈的底层向上逐项排查。

## Modbus RTU（RS-485）

1. **接线。** 各制造商对 A 和 B（或 D+ 和 D−，或 + 和 −）的命名并不一致。如果没有任何应答，把两根线对调一下：不会造成任何损坏。
2. **共地。** 设备有信号地（GND、C、0 V）时，请把它连上；长电缆如果没有共地，会出现时有时无的错误。
3. **终端电阻。** 在总线的两端各接一个 120 Ω 电阻，而不是每台设备都接。较短的台面电缆通常不接也能工作。
4. **串口设置。** 波特率、数据位、校验位和停止位必须完全一致。常见的出厂设置是 9600 或 19200 波特，8 位数据位，偶校验或无校验。校验位不一致不会有任何提示。
5. **单元 ID。** 总线上的每台设备都需要自己的地址，范围 1 到 247。设置为 1 的设备不会应答发给 2 的请求。参见[单元 ID](modbus-unit-id-slave-id)。
6. **只能有一个主站。** 同一条总线上有两个主站（例如 PLC 和笔记本电脑）会发生冲突。
7. **转换器的方向切换。** 廉价的 USB–RS-485 转换器在高波特率下有时切换方向太慢。请尝试较低的速率。

## Modbus TCP

1. **先确认能连到设备。** 对它执行 `ping`，并检查 502 端口是否开放。
2. **连接数限制。** 许多设备只接受少量 TCP 连接。工具如果一直保持连接不关闭，会把其他工具锁在外面，直到设备让这些连接超时。
3. **通过网关时的单元 ID。** 在 TCP 转 RTU 网关后面，单元 ID 用来选择串口设备，必须与其地址一致；有些网关自身需要 0 或 255。
4. **是否启用了 Modbus TCP？** 有些设备出厂时将其关闭，或者只在另一个端口上应答。

## 设备对部分请求有应答，对另一些没有

- 请求太大，或者跨越了寄存器表中的空隙，可能会返回异常，也可能被忽略。请读取较小的块。
- 有些设备需要在请求之间停顿（RTU 为 3.5 个字符时间，较慢的设备需要更长）。请调大轮询间隔。
- 有些设备要延迟几十甚至几百毫秒才应答；请先调大响应超时。
