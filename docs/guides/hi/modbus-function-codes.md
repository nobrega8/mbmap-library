# Modbus फ़ंक्शन कोड और रजिस्टर क्षेत्र

हर Modbus अनुरोध एक फ़ंक्शन कोड बताता है। वही तय करता है कि क्रिया क्या होगी और डिवाइस के किस क्षेत्र पर होगी।

| कोड | नाम | क्षेत्र | आकार |
|---|---|---|---|
| 01 | Read Coils | कॉइल (0x) | बिट, पढ़ना/लिखना |
| 02 | Read Discrete Inputs | डिस्क्रीट इनपुट (1x) | बिट, केवल पढ़ना |
| 03 | Read Holding Registers | होल्डिंग रजिस्टर (4x) | 16-बिट, पढ़ना/लिखना |
| 04 | Read Input Registers | इनपुट रजिस्टर (3x) | 16-बिट, केवल पढ़ना |
| 05 | Write Single Coil | कॉइल | चालू के लिए `0xFF00`, बंद के लिए `0x0000` लिखें |
| 06 | Write Single Register | होल्डिंग रजिस्टर | एक रजिस्टर |
| 15 (0x0F) | Write Multiple Coils | कॉइल | कई बिट |
| 16 (0x10) | Write Multiple Registers | होल्डिंग रजिस्टर | कई रजिस्टर |
| 17 (0x11) | Report Server ID | — | डिवाइस की पहचान, फ़ॉर्मैट डिवाइस तय करता है |
| 43 / 14 (0x2B/0x0E) | Read Device Identification | — | विक्रेता, उत्पाद कोड, संशोधन टेक्स्ट के रूप में |

## होल्डिंग या इनपुट?

मैनुअल की तालिका या उसके पते का उपसर्ग आपको बताता है: `3xxxx` को 04 से पढ़ा जाता है, `4xxxx` को 03 से। कुछ डिवाइस दोनों फ़ंक्शनों का उत्तर वही डेटा देकर देते हैं; दूसरे गलत फ़ंक्शन को अपवाद 01 (illegal function) से अस्वीकार कर देते हैं। अगर मैनुअल कोई उपसर्ग या फ़ंक्शन नहीं देता, तो पहले 03 आज़माएँ।

## लिखना

- 32-बिट मान के दो रजिस्टर 16 से एक साथ लिखने होते हैं; उसके हिस्सों को 06 से एक-एक करके लिखने पर डिवाइस में मिला-जुला मान रह सकता है, या वह अस्वीकार हो सकता है।
- कुछ डिवाइस केवल 06 स्वीकार करते हैं, कुछ केवल 16। मैनुअल की समर्थित फ़ंक्शनों की सूची तय कर देती है।
- 05 से लिखे जाने वाले कॉइल में ठीक `0xFF00` या `0x0000` होना चाहिए।

## MBMap मैप इसे कैसे दर्ज करते हैं

हर रजिस्टर में एक `area` (`coil`, `discrete`, `input`, `holding`) और एक `access` (`R`, `W`, `RW`) होता है; टूल इन्हीं से फ़ंक्शन चुनता है। मैप पहचान फ़ंक्शन 17 और 43 का भी वर्णन कर सकते हैं, ताकि टूल जाँच सके कि वह किस डिवाइस से बात कर रहा है।
