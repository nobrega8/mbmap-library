# Modbus unit ID (स्लेव ID): कौन-सा डिवाइस उत्तर देता है

हर Modbus अनुरोध में एक बाइट का unit ID होता है, जिसे स्लेव ID, स्लेव पता या डिवाइस पता भी कहते हैं।

## RS-485 (Modbus RTU) पर

- बस पर हर डिवाइस का अपना पता 1 से 247 तक होता है, जो उसकी स्क्रीन, DIP स्विच या कॉन्फ़िगरेशन सॉफ़्टवेयर से सेट होता है।
- पता 0 ब्रॉडकास्ट है: हर डिवाइस लिखावट पर अमल करता है और कोई उत्तर नहीं देता। 0 पर भेजी गई रीडिंग का कोई जवाब नहीं आता।
- किसी दूसरे पते पर सेट डिवाइस आपके अनुरोध को पूरी तरह अनदेखा करता है, इसलिए गलत unit ID मरे हुए डिवाइस जैसा दिखता है: आपको त्रुटि नहीं, [टाइमआउट](modbus-timeout-no-response) मिलता है।

## Modbus TCP पर

- सीधे IP से पहुँचा गया डिवाइस आमतौर पर unit ID को अनदेखा करता है या 1 की अपेक्षा करता है। कुछ 0 या 255 की अपेक्षा करते हैं, और कुछ अपने कॉन्फ़िगर किए मान के अलावा कुछ नहीं मानते।
- TCP-से-RTU गेटवे के पीछे unit ID सीरियल डिवाइस चुनता है: वह उस डिवाइस के RS-485 पते से मेल खाना चाहिए। गेटवे स्वयं अक्सर 0, 255 या कॉन्फ़िगर किए गए ID पर उत्तर देता है।
- कई आंतरिक हिस्सों वाले डिवाइस (मीटर और बैटरी वाला इन्वर्टर) हर हिस्से के लिए अलग unit ID पर उत्तर दे सकते हैं।

## अज्ञात पता खोजना

- इसे डिवाइस की स्क्रीन या लेबल से पढ़ें।
- स्कैन करें: डिवाइस की बॉड दर पर 1 से 247 तक हर पते पर किसी सामान्य रजिस्टर की रीडिंग भेजें और देखें कौन उत्तर देता है। केवल उसी डिवाइस को जोड़कर करें।
- फ़ैक्टरी सेटिंग पर रीसेट करें; मैनुअल डिफ़ॉल्ट बताता है (अक्सर 1)।

## MBMap मैप इसे कैसे दर्ज करते हैं

मैप डिवाइस का डिफ़ॉल्ट `unit_id` देता है (और सीरियल सेटिंग तथा TCP पोर्ट भी)। डिफ़ॉल्ट केवल शुरुआती बिंदु है: इंस्टॉल करते समय डिवाइस आमतौर पर फिर से कॉन्फ़िगर किए जाते हैं।
