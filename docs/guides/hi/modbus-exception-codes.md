# Modbus अपवाद कोड: डिवाइस आपको क्या बता रहा है

जब कोई Modbus डिवाइस अनुरोध को समझ लेता है पर उसे पूरा नहीं कर पाता, तो वह अपवाद के साथ उत्तर देता है: वह फ़ंक्शन कोड जिसका सबसे ऊपरी बिट सेट हो (होल्डिंग रजिस्टर पढ़ने की विफलता के लिए `0x83`) और एक बाइट का कोड।

| कोड | नाम | आम कारण | क्या आज़माएँ |
|---|---|---|---|
| 01 | Illegal function | डिवाइस इस फ़ंक्शन कोड का समर्थन नहीं करता: केवल होल्डिंग रजिस्टर वाले डिवाइस से इनपुट रजिस्टर (04) पढ़ना, या केवल 06 स्वीकार करने वाले डिवाइस पर 16 से लिखना | मैनुअल उस तालिका के लिए जो फ़ंक्शन कोड बताता है वही इस्तेमाल करें |
| 02 | Illegal data address | पता मौजूद नहीं है, या माँगा गया ब्लॉक किसी खाली अंतराल में चला जाता है | [पते का ऑफ़सेट](modbus-address-off-by-one) जाँचें; एक बार में कम रजिस्टर पढ़ें |
| 03 | Illegal data value | मात्रा बहुत बड़ी है (125 से अधिक रजिस्टर) या लिखा गया मान सीमा से बाहर है | छोटे ब्लॉक पढ़ें; लिखने से पहले अनुमत सीमा जाँचें |
| 04 | Server device failure | डिवाइस इसे करते समय विफल हुआ; कुछ डिवाइस इसे किसी भी अस्वीकृत लिखावट के लिए या ऐसे ब्लॉक को पढ़ने के लिए इस्तेमाल करते हैं जिसकी अनुमति नहीं है | एक बार में एक रजिस्टर पढ़ें; डिवाइस की स्थिति जाँचें |
| 05 | Acknowledge | स्वीकार कर लिया गया, पर कुछ समय लगेगा (प्रोग्रामिंग, सहेजना) | प्रतीक्षा करें, फिर पोल करें |
| 06 | Server device busy | डिवाइस व्यस्त है | बाद में फिर कोशिश करें |
| 0A | Gateway path unavailable | गेटवे अपने पीछे के डिवाइस तक नहीं पहुँच सका | गेटवे का सीरियल पक्ष और उसकी रूटिंग जाँचें |
| 0B | Gateway target failed to respond | गेटवे ने अनुरोध आगे भेजा पर डिवाइस ने उत्तर नहीं दिया | गेटवे के पीछे unit ID, बॉड रेट और वायरिंग जाँचें |

<mb-exceptions></mb-exceptions>

## कोई उत्तर न आना अपवाद नहीं है

जिस डिवाइस को गलत CRC, गलत unit ID या पैरिटी त्रुटि वाला फ़्रेम मिलता है, वह चुप रहता है: आपको टाइमआउट मिलता है, अपवाद नहीं। [टाइमआउट](modbus-timeout-no-response) देखें।

## अंतरालों को पार करने वाले ब्लॉक

कई डिवाइस ऐसी हर रीडिंग से मना कर देते हैं जो किसी अप्रयुक्त पते को छूती है, भले ही आपको चाहिए हर रजिस्टर मौजूद हो। अगर 20 रजिस्टर पढ़ना 02 से विफल होता है पर एक-एक करके पढ़ना चलता है, तो अनुरोध को अंतरालों पर बाँट दें। मैप बता सकते हैं कि डिवाइस प्रति अनुरोध कितने रजिस्टर स्वीकार करता है (`max_read_registers`)।
