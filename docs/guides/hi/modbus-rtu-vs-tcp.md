# Modbus RTU, Modbus TCP और RS-485

तीन नाम जो अक्सर आपस में मिल जाते हैं।

| | Modbus RTU | Modbus TCP |
|---|---|---|
| माध्यम | सीरियल लाइन, लगभग हमेशा RS-485 (कभी-कभी RS-232) | Ethernet या Wi-Fi |
| पता | बस पर unit ID 1–247 | IP पता और पोर्ट (502), साथ में एक unit ID |
| त्रुटि जाँच | हर फ़्रेम में CRC-16 | TCP की अपनी जाँचें; कोई CRC नहीं |
| फ़्रेमिंग | फ़्रेमों के बीच 3.5 अक्षरों की चुप्पी | लंबाई वाला 7-बाइट हेडर (MBAP) |
| प्रति लिंक डिवाइस | प्रति खंड 32 यूनिट लोड तक (कम-लोड ट्रांसीवर के साथ अधिक), एक मास्टर | प्रति डिवाइस कई क्लाइंट, डिवाइस की सीमा तक |
| आम गति | 9600–115200 बॉड | 10/100 Mbit/s, डिवाइस की सीमा तक |

**RS-485** केवल विद्युत परत है: दो तार, एक डिफ़रेंशियल सिग्नल, एक बस। Modbus RTU इसी पर चलता है, और अन्य प्रोटोकॉल भी (BACnet MS/TP, DMX, RS-485 एडेप्टर पर M-Bus)।

**Modbus ASCII** वही अनुरोध पढ़ने योग्य हेक्स टेक्स्ट के रूप में भेजता है; आज यह दुर्लभ है।

## वही रजिस्टर

परिवहन चाहे जो हो, रजिस्टर मैप वही रहता है: जो डिवाइस दोनों देता है, वह वही पते, प्रकार और स्केल के साथ उत्तर देता है। बदलता केवल यह है कि आप उस तक कैसे पहुँचते हैं: RTU में सीरियल सेटिंग और unit ID, TCP में IP पता और पोर्ट।

## गेटवे

Modbus TCP-से-RTU गेटवे Ethernet टूल को सीरियल डिवाइसों तक पहुँचने देता है। TCP अनुरोध का unit ID सीरियल पक्ष का डिवाइस चुनता है। गेटवे अपने टाइमआउट जोड़ते हैं; अगर उनके पीछे का डिवाइस उत्तर नहीं देता, तो पहले गेटवे की सीरियल सेटिंग जाँचें।

## MBMap मैप इसे कैसे दर्ज करते हैं

मैप बताता है कि डिवाइस कौन-से परिवहन देता है (`protocol`: `rtu`, `tcp` या दोनों) और उनके डिफ़ॉल्ट (`baudrate`, `parity`, `databits`, `stopbits`, `port`, `unit_id`)।
