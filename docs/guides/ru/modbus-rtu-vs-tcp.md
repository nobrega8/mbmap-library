# Modbus RTU, Modbus TCP и RS-485

Три названия, которые часто путают.

| | Modbus RTU | Modbus TCP |
|---|---|---|
| Среда | последовательная линия, почти всегда RS-485 (иногда RS-232) | Ethernet или Wi-Fi |
| Адресация | unit ID 1–247 на шине | IP-адрес и порт (502) плюс unit ID |
| Проверка ошибок | CRC-16 в каждом кадре | собственные проверки TCP; CRC нет |
| Кадрирование | тишина в 3,5 символа между кадрами | 7-байтовый заголовок (MBAP) с длиной |
| Устройств на линию | до 32 единичных нагрузок на сегмент (больше с маломощными приёмопередатчиками), один ведущий | много клиентов на устройство, ограничено устройством |
| Типичная скорость | 9600–115200 бод | 10/100 Мбит/с, ограничено устройством |

**RS-485** — это только электрический уровень: два провода, дифференциальный сигнал, шина. По нему работает Modbus RTU, а также другие протоколы (BACnet MS/TP, DMX, M-Bus через адаптеры RS-485).

**Modbus ASCII** отправляет те же запросы в виде читаемого hex-текста; сегодня он встречается редко.

<mb-adu></mb-adu>

## Те же регистры

Карта регистров не зависит от транспорта: устройство, которое предлагает оба, отвечает с теми же адресами, типами и масштабами. Меняется способ доступа: последовательные настройки и unit ID для RTU, IP-адрес и порт для TCP.

## Шлюзы

Шлюз Modbus TCP–RTU позволяет инструментам Ethernet обращаться к последовательным устройствам. Unit ID в TCP-запросе выбирает устройство на последовательной стороне. У шлюзов есть собственные тайм-ауты; если устройство за шлюзом не отвечает, сначала проверьте последовательные настройки шлюза.

## Как это записано в картах MBMap

Карта указывает, какие транспорты предлагает устройство (`protocol`: `rtu`, `tcp` или оба), и их значения по умолчанию (`baudrate`, `parity`, `databits`, `stopbits`, `port`, `unit_id`).
