# Compatibilidad

Herramientas que leen archivos `.mbmap` y qué partes del formato ([SPEC.md](SPEC.md)) admite cada una.

## Herramientas

| Herramienta | Qué es | Qué hace con un mapa |
|---|---|---|
| <img src="https://raw.githubusercontent.com/nobrega8/modbench/main/assets/icon.svg" width="20" height="20" alt="" align="top"> [Modbench](https://github.com/nobrega8/modbench) | Cliente Modbus TCP/UDP/RTU/ASCII para Windows, Linux y macOS, con línea de comandos (`modbench-cli`) y un servidor MCP | Abre un mapa y lee (y escribe en) el dispositivo por nombre de registro; explora y descarga esta biblioteca; ejecuta un dispositivo simulado con la forma de un mapa. Desde la línea de comandos: `validate` y `convert` mapas, y `map` lee de un dispositivo todos los registros de un mapa; las herramientas MCP `read_map` y `validate_map` hacen lo mismo para un asistente de IA |
| <img src="assets/tools/scanbus-br.png" width="20" height="20" alt="" align="top"> [ScanBus-BR](https://github.com/ortegahernandes/ScanBus-BR-Simulator-Modbus) | Maestro Modbus RTU/TCP gratuito, simulador de esclavo y sniffer RTU para Windows y Linux (desde la versión 5.2.0) | Busca en esta biblioteca y muestra los registros de un dispositivo (nombre, función, dirección); importa los nombres de los registros como alias y rellena la función, la dirección inicial, el tipo y el orden de bytes del primer registro, además del ID de unidad, la velocidad, la paridad y los bits de parada del mapa. Su tabla principal lee bloques contiguos (una dirección inicial y un número), no registros sueltos por nombre; al hacer clic en un registro se abre ese registro en una ventana aparte. Desde la 5.3.0, una ventana de registros (alfa) lista todos los registros del dispositivo elegido; la 5.3.1 añade un filtro y selectores de grupo de funciones y de firmware. Muestra el estado de cada mapa y guarda un mapa como CSV (solo los registros), TXT o RTF (con descripciones y notas) |
| <img src="assets/tools/mtui.png" width="20" height="20" alt="" align="top"> [MTUI](https://github.com/inowattio/MTUI) | Cliente Modbus TCP/RTU para el terminal, manejado con el teclado, para Windows, Linux y macOS, con una demostración web (desde la versión 1.6.0) | Importa un mapa pegado: cada registro se fija y se etiqueta con su nombre y unidad, y recibe una regla que decodifica su tipo, orden de bytes y de palabras, escala, desplazamiento y tabla de traducción. Los registros que no puede decodificar (cadenas, campos de varios bits) conservan solo la etiqueta |
| <img src="assets/tools/modbus-tools.png" width="20" height="20" alt="" align="top"> [Modbus Tools](https://github.com/serhmarch/ModbusTools) | Cliente Modbus (ModbusClient) y simulador de servidor (ModbusServer) para Windows y Linux, con TCP, UDP, RTU y ASCII (aún no en una versión publicada: la compatibilidad está integrada en la rama `v0.5dev`) | **Data › Import Data View…** e **Import Items…** aceptan un archivo `.mbmap.json`: cada registro pasa a ser un elemento de la vista de datos (dirección, formato, orden de bytes y de palabras, y un comentario con el nombre, la unidad, la escala y el desplazamiento), y la vista toma el nombre del mapa. Los campos de bits y los bits `bool` de un registro se convierten en un elemento `Bin16` por registro, con el comentario nombrando cada bit. La exportación no cambia |
| <img src="assets/tools/open-modscan.png" width="20" height="20" alt="" align="top"> [Open ModScan](https://github.com/sanny32/OpenModScan) | Maestro (cliente) Modbus gratuito para Windows y Linux (integrado en la rama `dev`, aún no en una versión publicada: la 1.16.2 no lo tiene) | File › Open acepta un archivo `.mbmap.json`: los registros se agrupan en ventanas por área, modo de visualización y orden de bytes (huecos de hasta 10 direcciones, dentro de los límites de lectura), cada una configurada con el tipo de punto, la dirección inicial, la longitud, el ID del dispositivo, la base de direcciones y el modo de visualización, y los nombres de los registros (con unidad y escala) como descripciones de las direcciones. Un mapa con más de 8 ventanas abre una lista para elegir. File › Device Map Library descarga el índice de esta biblioteca, muestra los mapas con un filtro y abre el elegido |

## Compatibilidad por función

Leyenda: **Yes** compatible · **Kept** se lee y se vuelve a escribir, sin mostrarse · **—** no compatible o no documentado.

| Versión 1 del formato, CSV (§10, obsoleta) | Yes: lo abre con una advertencia y lo convierte a la versión 2 | — | — | — | — |

| Registros de identidad, `role`, y `models` (§4.7, §9) | Yes: el dispositivo se comprueba con los modelos y el firmware del mapa | — | — | — | — |
| Identidad desde el dispositivo, `identify` con FC17 o FC43 (§4.8, §9) | Yes: se lee, se valida, se conserva al guardar el mapa y se compara con los modelos y el firmware del mapa mediante Check device (aplicación y línea de comandos). FC43 está completo. El constructor de mapas aún no tiene campos para ello | — | — | — | — |

## Añadir una herramienta

¿Estás creando una herramienta que lee `.mbmap`? Sigue [SPEC.md](SPEC.md) y compárala con los archivos de ejemplo de [`tests/`](tests/): cada uno enumera los diagnósticos que un lector debe comunicar. Después abre una pull request que añada tu herramienta a esta página, con lo que admite. La compatibilidad parcial es válida: indica qué partes lee y cuáles ignora.
