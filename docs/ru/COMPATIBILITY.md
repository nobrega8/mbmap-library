# Совместимость

Инструменты, которые читают файлы `.mbmap`, и то, какие части формата ([SPEC.md](SPEC.md)) поддерживает каждый из них.

## Инструменты

| Инструмент | Что это | Что делает с картой |
|---|---|---|
| <img src="https://raw.githubusercontent.com/nobrega8/modbench/main/assets/icon.svg" width="20" height="20" alt="" align="top"> [Modbench](https://github.com/nobrega8/modbench) | Клиент Modbus TCP/UDP/RTU/ASCII для Windows, Linux и macOS с командной строкой (`modbench-cli`) и сервером MCP | Открывает карту и читает (и записывает) устройство по имени регистра; просматривает и скачивает эту библиотеку; запускает имитацию устройства по карте. Из командной строки: `validate` и `convert` для карт, а `map` читает с устройства каждый регистр карты; инструменты MCP `read_map` и `validate_map` делают то же для ИИ-ассистента |
| <img src="assets/tools/scanbus-br.png" width="20" height="20" alt="" align="top"> [ScanBus-BR](https://github.com/ortegahernandes/ScanBus-BR-Simulator-Modbus) | Бесплатный ведущий Modbus RTU/TCP, имитатор ведомого и RTU-сниффер для Windows и Linux (начиная с версии 5.2.0) | Ищет в этой библиотеке и показывает регистры устройства (имя, функция, адрес); импортирует имена регистров как псевдонимы и подставляет функцию, начальный адрес, тип и порядок байтов первого регистра, а также unit ID, скорость, чётность и стоповые биты карты. Его основная таблица читает непрерывные блоки (начальный адрес и количество), а не отдельные регистры по имени; щелчок по регистру открывает его в отдельном окне. Начиная с 5.3.0 окно регистров (альфа) перечисляет все регистры выбранного устройства; в 5.3.1 добавлены фильтр и выбор группы функций и прошивки. Показывает статус каждой карты и сохраняет карту как CSV (только регистры), TXT или RTF (с описаниями и заметками) |
| <img src="assets/tools/mtui.png" width="20" height="20" alt="" align="top"> [MTUI](https://github.com/inowattio/MTUI) | Клиент Modbus TCP/RTU для терминала с управлением с клавиатуры, для Windows, Linux и macOS, с веб-демо (начиная с версии 1.6.0) | Импортирует вставленную карту: каждый регистр закрепляется и подписывается своим именем и единицей, а также получает правило, которое декодирует его тип, порядок байтов и слов, масштаб, смещение и таблицу перевода. Регистры, которые он не может декодировать (строки, многобитные поля), сохраняют только подпись |
| <img src="assets/tools/modbus-tools.png" width="20" height="20" alt="" align="top"> [Modbus Tools](https://github.com/serhmarch/ModbusTools) | Клиент Modbus (ModbusClient) и имитатор сервера (ModbusServer) для Windows и Linux с TCP, UDP, RTU и ASCII (пока нет в релизе: поддержка влита в ветку `v0.5dev`) | **Data › Import Data View…** и **Import Items…** принимают файл `.mbmap.json`: каждый регистр становится элементом представления данных (адрес, формат, порядок байтов и слов и комментарий с именем, единицей, масштабом и смещением), а представление получает имя карты. Битовые поля и биты `bool` в регистре превращаются в один элемент `Bin16` на регистр, в комментарии которого названы все биты. Экспорт не изменился |
| <img src="assets/tools/open-modscan.png" width="20" height="20" alt="" align="top"> [Open ModScan](https://github.com/sanny32/OpenModScan) | Бесплатный ведущий Modbus (клиент) для Windows и Linux (влит в ветку `dev`, в релиз пока не вошёл: в 1.16.2 его нет) | File › Open принимает файл `.mbmap.json`: регистры группируются в окна по области, режиму отображения и порядку байтов (пропуски до 10 адресов, в пределах лимитов чтения), в каждом заданы тип точки, начальный адрес, длина, ID устройства, основание адресов и режим отображения, а имена регистров (с единицей и масштабом) используются как описания адресов. Карта с более чем 8 окнами открывает список для выбора. File › Device Map Library скачивает индекс этой библиотеки, показывает карты с фильтром и открывает выбранную |

## Добавление инструмента

Создаёте инструмент, читающий `.mbmap`? Следуйте [SPEC.md](SPEC.md) и сверяйтесь с образцами файлов в [`tests/`](tests/): в каждом перечислена диагностика, о которой должен сообщать читатель. Затем откройте pull request, добавляющий ваш инструмент на эту страницу с описанием того, что он поддерживает. Частичная поддержка допустима: укажите, какие части он читает, а какие игнорирует.
